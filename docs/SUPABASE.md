# Connect Fur Disclosure to Supabase

Use project `zdpheikochvtjirgskuv`. The planner’s API endpoint is already set to `https://zdpheikochvtjirgskuv.supabase.co`. The dashboard URL is for administration.

1. Open the [SQL Editor](https://supabase.com/dashboard/project/zdpheikochvtjirgskuv/sql/new). Paste and run the full [migration](../supabase/001_owner_profiles.sql) once. It creates three new tables in one transaction. A name collision stops the transaction for inspection. There is no trigger on the shared users table.
2. Open [Settings → API Keys](https://supabase.com/dashboard/project/zdpheikochvtjirgskuv/settings/api-keys). Copy a **publishable** key beginning with `sb_publishable_`. This build accepts only that key type. Keep database passwords, secret keys and service-role credentials out of the website and GitHub.
3. In the **planner’s Vercel project**, open Settings → Environment Variables. Set **SUPABASE_PUBLISHABLE_KEY** to the copied key for Production and any preview deployments that should use this project. Redeploy. Vercel runs `npm run build` and serves `dist/`. The frontend is expected to contain the publishable key. Owner access is enforced by login and database row policies.
4. In [Authentication → URL Configuration](https://supabase.com/dashboard/project/zdpheikochvtjirgskuv/auth/url-configuration), **add** the exact deployed planner root, `https://groom.furdisclosure.com/`. For local testing, add `http://127.0.0.1:4381/`. Keep the existing project's Site URL and other redirects. Ensure Email sign-in and new signups are enabled for the intended audience. The app requests the project's standard email sign-in link and supplies its own return URL. Confirm the shared project's email provider can deliver to your test recipients; project templates or SMTP changes affect the other app as well.
5. Open the configured planner, enter an email and follow the link. Save an owner name, add two dogs and give each different defaults. Finish a groom, open its history entry, copy it, and change one spot or haircut detail. Both entries should remain in the selected dog’s history. Sign out, sign in again, and check the saved profile and both visits.

**Local setup.** Install Node 22.14+ and run `npm ci`. Copy `.env.example` to `.env.local`, set the same publishable key, then run `npm run dev`. The local file is ignored by Git. Guest planning is available without a key.

**Shared project behavior.** Supabase Auth uses the project's existing pool of identities. A Fur Disclosure profile is created when the owner saves their details. Only the Fur Disclosure tables are written by this app. Each row belongs to the signed-in owner. Composite keys keep dog history and copied visits within the same owner and dog. Clients can insert and read their completed plans. Changes to an earlier groom are saved as a new record.

**What is stored.** `fd_owner_profiles` contains the owner's display name and optional phone. The account email comes from the authenticated Supabase session. `fd_dogs` contains identity, birthday and a JSON object of usual preferences. `fd_grooms` contains service, optional visit date, copy source and a dated JSON snapshot. For this iteration, the snapshot includes resized photo data and coordinates so a historic plan can be reproduced. The history list fetches only dates, IDs and service labels. A full snapshot is fetched when opened. Only completed grooms sync across devices. In-progress drafts belong to one account, dog and browser tab and clear on sign-out.
