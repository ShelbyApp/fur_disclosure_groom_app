# Landing-page public gallery

Migration [007_public_gallery.sql](../supabase/007_public_gallery.sql) extends 006 for the separate landing repository. Then run [008_lookbook_inspiration.sql](../supabase/008_lookbook_inspiration.sql) to import the eight existing AI portraits, followed by [009_restore_public_uploads.sql](../supabase/009_restore_public_uploads.sql) to restore public uploads awaiting review and prioritize real uploads on the landing page. Existing installations with 008 need only 009. Migration 009 is safe to rerun and changes selection functions only, preserving customer visibility, scores, upload dates and image data. Apply migrations in order.

- `quality_score`: internal nullable integer 1–10. Public user uploads with no review yet (null) remain eligible while review tooling is developed; 2–10 qualify and 1 is excluded. Browser users cannot assign or edit quality scores, and no scores are invented for existing uploads. The landing page selects up to eight real public uploads newest first, then fills remaining places with eligible AI inspiration, with date/ID descending within each group. The full gallery includes both groups with stable date/ID pagination. There is no random selection or browser sample fallback.
- `fd_lookbook_inspiration` stores the original eight JPEG portraits with starter scores of 8/10. It is admin-only, with no browser read/write grants. Public metadata and image RPCs include published, qualifying inspiration alongside real uploads through `fd_gallery_source`. AI entries have uploader category `inspiration`, no owner/groomer/location, and are labeled AI style inspiration. They appear only in Everyone/all-locations results. Ratings and publication can be edited in the Supabase SQL/Table Editor. No automated AI review has run.
- `uploader_type`: owner/groomer account category, assigned by a database trigger from signup metadata. Existing photos are backfilled once. It is not business verification. Photos generated from groom snapshots remain private by default.
- Public metadata, individual image, featured selection and location search RPCs provide the gallery with no owner/contact/health/history exposure. The existing owner/private photo policies remain intact. Insert grants are narrowed to prevent forging quality scores or uploader categories.
- Gallery location filters use a photo's tagged directory provider and its coverage cities. They never use the owner's profile address.

The landing page requires `SUPABASE_PUBLISHABLE_KEY` in its own Vercel project. Gallery UI and setup/scoring instructions are in that repository's `docs/lookbook.md`. Public score exclusions and visibility changes apply on subsequent reads; previously downloaded photos cannot be recalled. AI review and contests are not implemented yet.

Run `npm test` to include `test/public-gallery.test.mjs`, which applies the migrations in PostgreSQL/PGlite and checks permissions, quality selection, uploader roles, paging, mobile coverage, public projections, the existing groom-photo trigger, all eight seeded images, ordering, seed idempotency and public exclusion rules. The 009 regression test recreates two older unrated user uploads plus eight newer AI imports, verifies both metadata and image reads, preserves customer data, and checks that further uploads replace inspiration rather than displacing other user photos. Migration 008 is generated in the landing repository using `scripts/build-lookbook-seed.mjs`; keep SQL copies in both repositories identical.
